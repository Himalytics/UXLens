# Nielsen Usability Heuristics

This file summarizes widely used usability heuristics for interaction design.

## Visibility of System Status
Interfaces should keep users informed about what is happening through timely and appropriate feedback. After an action such as saving, uploading, paying, or submitting, the system should make the resulting status understandable. Long-running operations should provide progress or state information when useful. Lack of feedback can cause uncertainty, repeated actions, or loss of trust.

Design guidance: acknowledge actions; show progress for meaningful waits; communicate success, failure, and current state; avoid leaving users unsure whether the system received their input.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## Match Between the System and the Real World
Interfaces should use language, concepts, sequences, and conventions that are familiar to the intended users. Internal technical terminology should not replace words users naturally use. Information should appear in an order that fits users' expectations and mental models when possible.

Design guidance: prefer familiar terms; avoid unexplained jargon; organize tasks in a natural sequence; use recognizable representations when they improve understanding.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## User Control and Freedom
Users sometimes select the wrong option or change their minds. Interfaces should provide clear ways to cancel, go back, undo, exit, or recover without forcing users through unnecessary steps. Destructive actions deserve particular care.

Design guidance: provide undo where feasible; offer cancel or back controls; require meaningful confirmation for consequential destructive actions; avoid trapping users in a workflow.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## Consistency and Standards
Users should not have to wonder whether different words, icons, colors, or actions mean the same thing. Interfaces should follow internal consistency and platform conventions so that existing knowledge transfers to new screens and tasks.

Design guidance: use the same terminology for the same concept; keep controls visually and behaviorally consistent; follow familiar platform patterns unless there is a strong reason not to.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## Error Prevention
A strong interface tries to prevent problems before they occur. Designers should remove error-prone conditions where possible and check important choices before users commit to them. Constraints, sensible defaults, previews, and confirmations can reduce avoidable mistakes.

Design guidance: validate inputs at useful moments; disable impossible choices when appropriate; preview high-impact changes; confirm irreversible actions; preserve valid user input after an error.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## Recognition Rather Than Recall
Interfaces should reduce the amount of information users must remember from one part of the experience to another. Important options and instructions should be visible or easy to retrieve when needed.

Design guidance: expose relevant choices; provide examples and contextual help; preserve recent values when appropriate; avoid requiring users to memorize codes, labels, or earlier instructions.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## Flexibility and Efficiency of Use
Interfaces can support both new and experienced users. Accelerators such as shortcuts, saved preferences, templates, and personalization can improve efficiency without making the basic path difficult to discover.

Design guidance: keep the default workflow understandable; add shortcuts for frequent users; allow repeated work to be streamlined; do not make efficiency features mandatory for beginners.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## Aesthetic and Minimalist Design
Interfaces should avoid irrelevant information and unnecessary visual competition. Every extra element can compete with important content for attention. Minimalism does not mean removing useful context; it means emphasizing what supports the user's task.

Design guidance: prioritize important actions and information; group related content; remove redundant decoration; progressively disclose advanced options when appropriate.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## Error Recognition Diagnosis and Recovery
When errors occur, messages should explain the problem in understandable language and help the user recover. Error messages should identify what went wrong and indicate a constructive next step rather than displaying only an error code.

Design guidance: connect messages to the affected field or action; preserve valid work; explain how to fix the problem; avoid blaming the user; make recovery steps concrete.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/

## Help and Documentation
Even well-designed interfaces sometimes require assistance. Help should be easy to find, focused on the user's task, and concise enough to act on. Contextual support can be more useful than forcing users to search a large manual.

Design guidance: provide task-focused help; use concise steps; put guidance near difficult interactions; make documentation searchable when the domain is complex.

Reference: https://www.nngroup.com/articles/ten-usability-heuristics/
